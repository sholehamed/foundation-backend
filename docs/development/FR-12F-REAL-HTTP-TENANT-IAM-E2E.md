# FR-12F — Disposable real HTTP + SQL Server Tenant IAM chain

2026-11-08. Following FR-12E infrastructure write-intent enforcement.

## What is tested
An independent GitHub Actions job runs real ASP.NET Core Kestrel, a disposable SQL Server 2022 service, and real signed OpenIddict JWTs generated by the existing Development CAPTCHA/password endpoint. It does not forge JWTs, mock Identity principals, bypass TenantResolutionMiddleware or rely on EF InMemory.

1. Migrate the disposable Development test database (Shinera_E2E_* prefix), seed the existing Admin and Tenant E2E fixtures.
2. A separate CLI, NOT referenced by the production Web app, adds a test-only Owner role to the E2E Tenant and a role-free staff account. The CLI enforces Development, explicit opt-in, local loopback SQL and a disposable database prefix.
3. Live System SuperAdmin calls the System Feature Registry Tenant catalog preview and fingerprint-bound apply; stale fingerprint returns 409, non-System caller returns 403; catalog metadata has nine keys. The Apply opt-in flag is ON only in the disposable CI job and defaults OFF elsewhere.
4. Tenant Owner creates an ordinary role, grants TENANT.MEMBERS.READ, and assigns that role to staff. The existing signed staff JWT switches from 403 to 200 without re-login, and ui-access/me follows the same live permission evaluation.
5. Revoking the RolePermission, deactivating the role and revoking the UserRole all revoke staff access immediately; granting/reactivating restores it.
6. Stale SQL RowVersion returns 409, unknown/foreign code and role IDs are denied, reserved Owner role names and editing the Owner target are denied, anonymous/system/staff calls and forged X-Tenant-Id are denied.
7. A separate SQL-only verifier reads committed TenantRoleChangeAuditEntries, TenantRoleGrantAuditEntries and TenantMemberRoleAuditEntries and confirms SQL denies UPDATE of immutable audit rows.

The new Python script is tests/http/tenant_iam_chain_e2e.py. The SQL-only fixture and audit verifier are in tests/Shinera.Identity.E2E.SqlMutator. Failure exits nonzero. Static credentials in CI are disposable test credentials, not shared or production secrets.

## Not a browser BFF cutover
The test is real HTTP + SQL Server for CURRENT bearer-token Tenant APIs, NOT Chromium / deployed BFF Cookie E2E. BFF TestServer tests already separately validate OpenIddict discovery, Authorization Code+PKCE, opaque cookie and session revalidation. Angular still retains legacy token login, and Identity:Bff:Enabled remains false by default.

Still pending: real HTTPS reverse-proxy origins, Angular Chromium authorization redirect and Cookie flows, BFF CSRF validation for unsafe operations, browser route guard/tenant-host isolation, cross-repository browser CI with the same SQL fixture and reviewed BFF cutover. No production migration/catalog/grant is executed by this CI or merge. See backend Issue #44.
